# Opportunities

This directory is the portfolio-level starting point for selecting a service product before Phase 01.

Use it in this order:

```text
1. service-products.md
   choose the service market / product family
        ↓
2. service-models.md
   choose how that service is discovered, sold, scheduled, delivered, or managed
        ↓
3. combine Family ID + Model ID(s) + vertical variant
        ↓
4. create the Selected Opportunity Brief
        ↓
5. enter Phase 01
```

## Files

- [`service-products.md`](service-products.md) — broad catalog of service-product families, ordered by directional Iran demand and digital maturity.
- [`service-models.md`](service-models.md) — normalized reusable product-model taxonomy with English-language web references.
- [`iran-demand-methodology.md`](iran-demand-methodology.md) — methodology and caveats behind the Iran demand / digital-maturity labels.

## Selection format

A real project should be more specific than a vertical name.

Prefer:

```text
Family: EDU-TUTOR
Models: M01 + E02
Variant: subject-specialist tutor marketplace with recurring 1:1 lessons
```

instead of:

```text
Project: tutoring website
```

Or:

```text
Family: HOME-CLEANING
Models: M02 + S01 + D03
Variant: managed marketplace with recurring scheduled home cleaning
```

The family tells us **what service problem space** we are entering. The model tells us **how the product works**.

## Library rule

Do not create a separate family every time a new business niche appears if it can be expressed cleanly as an existing family plus a different model/variant.

Add a new family only when the service domain introduces meaningfully different users, problems, or workflows. Add a new model only when the service-delivery mechanics are genuinely different from the existing taxonomy.
